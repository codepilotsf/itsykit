Getting Started

Build your first ItsyWeb site, step by step: two HTML pages, shared navigation, a layout, a partial, and a little CSS.

Before you begin

In this tutorial, you'll build a two-page website for a fictional shop called Little Bookshop. You'll write the pages, link them together, change their shared header, and reuse opening hours in both places.

You need basic HTML and CSS, a text editor, and a terminal on an Apple Silicon Mac or x86-64 Linux computer. Install Git if you want ItsyWeb to create the initial repository and save your work in commits. You won't need a hosting account or a domain for this tutorial.

ItsyWeb serves your HTML and assembles shared templates as each page is requested. You can build this entire site without a database, a frontend build step, or an admin login.

1. Install ItsyWeb

Open a terminal and run:

curl -fsSL https://itsyweb.dev/install.sh | bash

The installer puts itsy in ~/.local/bin. Make it available in this terminal and check that it runs:

export PATH="$HOME/.local/bin:$PATH"
itsy version

You should see the installed ItsyWeb version. If the installer asks you to add ~/.local/bin to your shell's PATH, follow its instructions so future terminals can find it too.

The current release is a public test release. For platform details, direct downloads, or upgrading an existing installation, see Installation and updates.

2. Create a site

In a folder where you keep projects, run these commands one at a time:

itsy new little-bookshop
cd little-bookshop
itsy dev

The first command creates a new folder with a small working site. The second moves your terminal into that folder. The third starts the development server.

When prompted for a site name, enter Little Bookshop. Press Enter to skip the optional admin email. This tutorial keeps the content in HTML; you can add browser editing later.

Open the Website URL printed in the terminal. It normally uses port 3000; if that port is busy, ItsyWeb chooses the next available one. You should see the default welcome page. Leave this terminal running while you edit files.

If little-bookshop already exists, choose a different folder name or use a completely empty directory. ItsyWeb won't overwrite an existing project.

3. Find your files

Open the little-bookshop folder in your text editor. For now, you'll work with these files:

site/index.html
The homepage, served at /.
site/main.layout.html
The shared document, header, and footer around each page.
site/_navigation.html
The links used by both desktop and mobile navigation.
site/css/global.css
Shared CSS, including the theme and utility imports.
itsy.config.json
Site settings, including the name you just entered.

Public URLs leave out site/. For example, a file at site/images/shop.jpg would be available at /images/shop.jpg.

The other generated folders support optional features such as email and editable content. You can leave them as they are.

4. Write the homepage

Replace the contents of site/index.html with:

<section class="container py-xl">
  <h1>Little Bookshop</h1>
  <p>Good books, a quiet corner, and time to browse.</p>
  <a href="/visit">Plan your visit</a>
</section>

Save the file. The browser reloads and shows your new heading and introduction, surrounded by the generated header and footer. The container and py-xl classes use the included Prewind styles to give the page a readable width and some space.

You've added a link to /visit. It will return 404 until you create that page in the next step.

The default homepage used references to editable content. Replacing that example is fine here: your new text lives directly in HTML and changes when you edit the file.

5. Add a second page

Create site/visit.html with:

<section class="container py-xl">
  <h1>Visit the bookshop</h1>
  <p>Find your next read at our little shop.</p>
  <p><a href="/">Back to the homepage</a></p>
</section>

Save it, then follow Plan your visit from the homepage. You should see the new page with the same header and footer. Use Back to the homepage to return.

To put both pages in the shared navigation, replace site/_navigation.html with:

<a href="/">Home</a>
<a href="/visit">Visit</a>

Save and check that Home and Visit work from either page. These links also appear in the generated mobile menu.

A page file creates its route automatically: site/visit.html becomes /visit. Link to that clean URL, without .html or a trailing slash.

6. Change the shared layout

Open site/main.layout.html. It contains the full HTML document. Find {slot} inside its <main> element:

<main class="flex-1 flex flex-col">{slot}</main>

ItsyWeb puts the current page's content at that slot. This is why your page files only need a section rather than a second <html>, <head>, or <body>.

Inside the existing <header>, add this paragraph after the outer navigation block, just before </header>:

<p class="container py-xs">Independent books. Curious readers.</p>

Save, then open Home and Visit. The new line appears above both pages even though you changed only the layout.

Keep the rest of the generated layout, including its admin conditionals, CSRF meta tag, and toolbar include. They support optional editing if you enable it later.

7. Reuse a partial

Opening hours belong on both pages. Create site/_hours.html:

<p>Open Tuesday to Saturday, 10am to 6pm.</p>

In both site/index.html and site/visit.html, add this line inside the section, just before its closing </section>:

{render hours}

Save and check both pages. They should now show the same hours. Change 6pm to 7pm in site/_hours.html and save again. Both pages use the updated text.

The underscore makes _hours.html a private partial rather than a public page. The render instruction leaves off the underscore and file extension, and looks beside the file that includes it.

8. Add a little CSS

Open site/css/global.css. Inside its existing @layer styles block, add:

h1 {
  color: var(--brand-1);
}

Save. The main heading on both pages now uses the theme's primary brand color. Regular CSS works here, and changes appear without running a build command.

Colors, fonts, and spacing tokens live in site/css/theme.css. Follow CSS and icons when you're ready to make the design your own.

9. Check and save your work

Open a second terminal, move into little-bookshop, and run:

itsy status

You should see a local validation summary with two public pages. Because this project has no saved deployment destination, status finishes locally. If it reports a template error, use the file and line it names, correct the markup, and run it again.

Click Home and Visit once more. Check that both pages have the shared header, opening hours ending at 7pm, and the heading color you added.

If Git setup succeeded, ItsyWeb already made an initial commit when it created the site. Review and save your changes:

git status --short
git diff
git add site itsy itsy.config.json
git commit -m "Build the Little Bookshop site"

If site creation reported a Git identity or commit problem, follow its recovery instructions first. The local site still works.

When you're finished, press Ctrl-C in the terminal running itsy dev. Run itsy dev from this folder whenever you want to work on the site again.

You now have two HTML pages, shared navigation and a layout, a reusable partial, and CSS you can change directly.
