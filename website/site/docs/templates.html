Pages, layouts and data

Map files to URLs, share markup with layouts and partials, and use JSON data.

A folder you can follow

site/
Public HTML, CSS, images and other assets.
site/main.layout.html
The shared page wrapper.
itsy/snips.json
Editable content and page metadata.
itsy/data/
Optional JSON data you maintain in code.
itsy/media/
Managed photos and videos.
mailers/
Private email templates.
itsy.config.json
Site settings and branch deployment destinations.
itsy/runtime/
Private, Git-ignored runtime state.
itsy/skills/
Portable instructions for coding agents.

Public URLs leave off site/. For example, site/images/logo.svg is served at /images/logo.svg. Keep secrets out of configuration, templates and Git.

HTML, with reusable pieces

Keep page content in HTML files. The server handles the shared pieces when it serves a page, so you do not need to run a static site generator after changing your header.

Add a page

Create site/about.html for /about. You can use site/about/index.html instead, but not both. Link to extensionless URLs without a trailing slash. Explicit .html URLs and trailing slashes return 404 unless you configure an exact redirect. Assets keep their paths: site/images/logo.svg is /images/logo.svg. Files and directories beginning with _ or . are private.

Share a layout

The default wrapper is site/main.layout.html. Put {slot} where the page content belongs.

<header>Our studio</header>
<main>{slot}</main>
<footer>Thanks for stopping by.</footer>

For a different wrapper, put this comment at the very start of a page:

<!-- itsy
layout: /custom.layout.html
-->

Preserve the generated layout's app.current_admin conditional blocks, CSRF meta tag and admin toolbar include. They allow the optional editor to work if you enable admin access later; they do not require you to make your page content editable.

Reuse a partial

Put navigation, a card or any other shared markup in a private partial. Include it wherever you need it; editing the partial updates every page that uses it.

Create site/_card.html, then include it with {render card}. Relative names resolve beside the calling template. {render /shared/card} selects site/shared/_card.html.

Settings and structured data

Public settings live under app in itsy.config.json. Use {app.site_name} in your templates. A file named itsy/data/team.json is available as data.team.

{#if app.phone}
  <p>Call {app.phone}</p>
{/if}

{#each data.team.members as member}
  <p>{member.name}</p>
{:else}
  <p>Meet the team soon.</p>
{/each}

Conditions take dotted paths, not JavaScript expressions. Use {#unless app.phone}...{/unless} for a negative condition. Both support {:else} and {:else if dotted.path}.

Page titles and descriptions

Page metadata lives under the route in pages in itsy/snips.json. Update its title and description fields. The layout can use {page.title}, {page.description} and {page.path}. Ordinary page text can stay directly in your HTML.
