Migration redirects

Map old paths directly to their replacements with exact 301 redirects.

Preserve old links with 301 redirects

From ItsyWeb 0.20.0, keep visitors and search engines reaching the right content when you migrate a site or move a page. Add exact old paths to a top-level redirects object in itsy.config.json, alongside app:

{
  "app": {"site_name": "Example"},
  "redirects": {
    "/about-us.html": "/about",
    "/services/": "/services",
    "/old-team.php": "/about#team"
  }
}

GET and HEAD requests for a listed path return 301 Moved Permanently. Sources match exact, case-sensitive paths, including explicitly listed old extensions and trailing slashes. Unlisted legacy URLs still return 404. These rules never redirect POST or other mutation requests.

Destinations must be existing public pages or assets on this site, including published Blog posts. They may include a query or fragment. Incoming queries survive unless the destination supplies a query of its own; a destination ending in ? explicitly clears it. ItsyWeb decodes source paths once and rejects duplicate decoded sources, unsafe/private paths, conflicts with active pages, assets or managed app subtrees, and redirect chains or loops. Former Blog slugs can be explicit sources. Update their redirects when removing a destination.

There are no wildcard, regex, query-specific or external-URL rules. An old site that uses different pages at /?p=123 and /?p=456 needs a separate migration decision. Path rules do not configure DNS, certificates or arbitrary hostname redirects. Existing HTTP-to-HTTPS and WWW redirects continue to use 308.

Inventory the original website with an agent

Ask your coding agent:

Use itsy-site to inventory https://example.com and prepare 301 redirects for this Itsy site.

The skill reads public sitemaps and internal links, preserves useful URLs, maps moved content to real replacements and records ambiguous or unsupported URLs. Supply old URL lists or analytics exports when available: a live crawl cannot discover every orphaned page. Full brochure imports include this step too. Existing sites can copy the matching skill from a fresh temporary site; updating the CLI does not replace project instructions.

Validate before deploying

Run itsy status, then use a local dev server to check each old URL without following redirects. Confirm its 301 and Location, then check the destination serves the intended content in one hop. Check query behavior and unchanged URLs too.

Update both CLI and server. This feature requires deployment protocol 28. Run itsy update, then explicitly update the shared server with itsy update-server before deploying rules. Public 0.19.0 and earlier ignore site redirect settings.
