ItsyWeb Guides

Blog

Enable a blog, customize its templates, and create and publish posts.

Enable a blog

Blog is an optional built-in content application. It adds a public post list and individual post pages, plus a basic admin editor using ItsyWeb’s existing sign-in, rich text and photo library. No database or extra service is required.

Requires ItsyWeb 0.15.0 or newer and a current server. The public installer downloads 0.21.0, which includes Blog, and 0.21.0 uses server protocol 29. Enable it explicitly in each site; a CLI update does not change existing project files.

1. Enable it in your site configuration

Merge this into itsy.config.json, preserving your other settings and apps:

{
  "apps": {
    "blog": {
      "mount": "/blog"
    }
  }
}

The mount owns /blog and its entire URL subtree, so ordinary pages and assets cannot occupy those URLs. Removing the Blog configuration disables its routes without deleting stored posts.

2. Add the templates

Sites created with ItsyWeb 0.15.0 include these private templates. For an existing site, generate a fresh temporary site with the matching CLI and copy these files, preserving your site’s custom layout:

  • site/blog/_index.html for the public list.
  • site/blog/_post.html for individual posts.
  • site/admin/blog.html and site/admin/blog-edit.html for the admin screens.

Copy the Blog rules from the fresh site’s site/css/global.css into your own stylesheet. Keep your existing styles and layout. If you choose another mount, move the two public templates under that directory while keeping their private filenames. Add an admin link to /admin/blog, or visit it directly.

3. Preview, commit and deploy

itsy dev
# Check your site locally, then stop dev and commit the changes.
itsy deploy

Both the local CLI and the destination server need the matching version. An explicit itsy update-server updates the shared server and briefly restarts every site on that host; back up first. Updating a server does not add Blog templates or enable Blog on existing sites.

Create and publish posts

Sign in at /admin, then open /admin/blog. Choose New post, enter a title, slug, excerpt and rich body, and optionally select or upload a cover photo. Save creates a draft. Publish makes it public; Unpublish makes it private again. Saving an already published post updates it immediately. Cancel discards unsaved changes.

Published posts appear at /blog and /blog/<slug>. Draft text stays out of public routes and template data, and a draft URL returns 404. Photo files are public assets, including covers attached to drafts. Covers use the existing JPEG/PNG photo processing; inline body photos are not supported.

Leave the publication date empty to assign it when first publishing, or enter an RFC3339 date such as 2026-10-13T14:00:00Z. A future date publishes immediately, not on a schedule. Lists show the newest publication dates first. Changing a slug changes the URL without creating a redirect automatically. Add an explicit migration redirect for the old slug when needed.

Post JSON for agents and developers

The add-blog agent skill documents this setup and the supported template values.

Posts use the optional top-level blog array in itsy/snips.json. Preserve the existing pages, shared, archive and media values. Here is one draft post:

{
  "blog": [
    {
      "id": "a7Km2pQ9xB",
      "title": "Welcome",
      "slug": "welcome",
      "excerpt": "Our first article.",
      "body": "<p>Welcome to our website.</p>",
      "status": "draft"
    }
  ]
}

Keep the ten-character, case-sensitive alphanumeric ID stable through edits. Slugs must be unique across drafts and published posts, using lowercase letters, digits and separating hyphens, up to 100 characters. Titles are required and limited to 200 characters; excerpts to 500. The limit is 200 posts and 1 MiB per body, within the existing 5 MiB content file. Status is draft or published; published records require published_at. An optional cover references an existing ID in the media map, never a filename or URL.

Template values

The listing template can iterate published posts:

{#each blog.data.posts as post}
  <article>
    <h2><a href="{post.url}">{post.title}</a></h2>
    <p>{post.excerpt}</p>
  </article>
{:else}<p>No posts yet.</p>
{/each}

The post template receives blog.data.post, including title, excerpt, URL, publication date, body and an optional cover object with src, alt, width and height. The listing URL is blog.data.url.

<h1>{blog.data.post.title}</h1>
<time datetime="{blog.data.post.published_at}">
  {blog.data.post.published_label}
</time>
<div>{blog.data.post.body}</div>

Only the exact {blog.data.post.body} directive renders sanitized rich HTML, and only in ordinary element content. Other values remain escaped. Never put the body directive in an attribute, script or textarea. Braces inside a post body are ordinary text, not template source.

Keep live edits when deploying

Normal itsy deploy preserves live posts by ID and seeds new source-only IDs. Before an agent edits existing live posts in Git, run itsy pull. Publish reviewed source changes with itsy deploy --with-snips; this existing flag includes Blog records and cover metadata. Conflicting edits require a whole-post choice, and noninteractive conflicts stop.

Omitting a post from source never deletes its live record. Unpublish it to remove its public page. Backups include live posts and covers; rollback keeps current content while selecting earlier code. Comments, categories, tags, search, scheduling and revision history are deferred.
