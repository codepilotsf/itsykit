ItsyWeb Guides

Local development

Create projects, use live reload, and test from another device on your network.

Your first HTML site

Create a project and start the local server:

itsy new my-site
cd my-site
itsy dev

Enter a site name when prompted. The admin email is optional; skip it to start with the HTML workflow. Open the Website URL printed in the terminal.

Edit a page

Replace the contents of site/index.html with your own markup:

<h1>Hello, from our little corner.</h1>
<p>A website made with HTML and CSS.</p>

Save the file and the browser reloads. The default site/main.layout.html supplies the document wrapper, header and footer. Edit those once to change them across the site. Your page markup goes where the layout has {slot}.

Create site/about.html and visit /about. There's no route configuration or generated output directory. See pages, layouts and partials for the template syntax, then put the site online.

Check and save

itsy status

Status validates the project without rewriting it, shows page, asset and editable-area counts, and reports Git state. When the current branch has a saved deployment, it also checks that destination over SSH. The remote report separates website reachability, deployed code and editable content; a previous pull baseline is needed to identify which side changed. Without a saved destination, status finishes locally.

New projects have a Git repository on main with an Initial site commit. Review and commit your changes before deploying. The creation command prints instructions to connect and push to your remote repository; it does not create a remote for you. Use --skip-git to skip Git setup. A failed initial commit leaves the usable site and instructions to retry.

Other ways to start

Already in an empty project folder? Run itsy new .. Relative and absolute directory paths work too. ItsyWeb creates a missing directory when its parent exists. Existing directories must be completely empty, including hidden files and .git; files and directory symlinks are refused. The folder name supplies the default site name. Use itsy new --starter my-site or -s for example pages instead of the clean homepage.

Dev starts at port 3000 and explains occupied ports before trying 3001, 3002 and so on. An explicit --port stays fixed; --port 0 lets the operating system choose. Running itsy dev again replaces this site's running dev server, including when changing ports or LAN mode. Pull and reset are never interrupted. Stop any dev process started with an older binary manually once.

Test on another device

To use a phone, tablet or another computer on the same trusted network, start dev with:

itsy dev --lan

itsy dev -l does the same thing. ItsyWeb prints Network and Hostname URLs for detected private/Tailscale IPv4 addresses and this computer's name/local alias. Open a printed URL, such as http://studio:3000, when that name resolves to the dev computer. Its /admin link opens sign-in. Exact Host/port and peer checks remain required. Without the flag, dev stays accessible only on your computer using the printed Website URL.

This is the full dev site: approved admins can sign in, edit text and collections, upload photos and videos, and save changes. Contact forms, browser reloads and dev diagnostics work over the network too. Each device signs in separately.

Sign-in codes and email previews

With email preview enabled, messages still open on the computer running ItsyWeb. Enter the code on your other device. To share a private preview, replace its loopback IP with the printed network IP, keeping the port and random path. Anyone with that link and network access can read the message, so keep it private. There is no public inbox.

LAN mode uses unencrypted HTTP. Use it only on a trusted network, never forward the development port, and restart dev after changing networks. VPN addresses may also appear. Your firewall must allow the selected port; guest Wi-Fi can block connections between devices. Use --port 3001 if you need a different port.
