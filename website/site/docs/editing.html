On-page editing

Make selected content editable, enable admin access, and sync live changes.

When you need more than templates

The HTML, development and deployment workflow works without these features. Add on-page editing when someone else needs to change content, or enable an app when the site needs a blog, a contact form or custom server-side behavior.

These guides cover that extra functionality. You can leave ordinary page content in HTML and come back here when you need it.

Optional on-page editing

Use snips only for content an admin should change in the browser. Layouts, partials and ordinary HTML pages do not need them. Leave developer-managed text in the template.

A snip is a piece of content the admin can change. Mark an element with a bare snip attribute:

<section snip>
  <h2>Made just around the corner.</h2>
  <p>Visit our studio on Saturday.</p>
</section>

Dev extracts the inner HTML into JSON and replaces it with a generated snip directive. Let ItsyWeb generate the ID and keep it unchanged. The JSON entry becomes the source of the editable value.

Classes, layout and other attributes stay in the template. Don't nest snips or put template directives inside a new editable region. Use dedicated image and video snips for media.

Admins can format text and edit page titles and descriptions using Page details. Changes are published with the page's Save button.

Hand over the editing

Add an approved admin from your site folder:

itsy admin admin@example.com

This adds the address to admin.emails. Admins visit /admin and sign in with an emailed code. All approved admins have the same editing access.

Editing starts enabled. Click text or media, make changes, then use Save or Cancel. Both keep editing on. Save updates the page in place without reloading it; Cancel returns to the latest successful save.

New local sites preview email in the browser without sending it. Production needs HTTPS and real email delivery. Commit and deploy admin-list changes before sharing the live sign-in link.

Sessions have a default 30-day idle window. Set admin.session_idle_days to a value from 1 to 365. An empty admin list disables live sign-in.

Sync optional editable content

Keep admin changes

Normal deployment preserves live editable content and publishes committed CSS. To bring those edits into your local project, stop dev and run:

itsy pull

Pull retrieves live content and referenced media. Review and commit the result.

To deliberately publish local content edits, first establish a pull baseline, then run:

itsy deploy --with-snips

Conflicts require an explicit choice between the live and local changes.
