CLI reference

Commands and options for creating, developing, deploying, and managing Itsy sites.

Command help

itsy help
itsy deploy --help
itsy server --help

Run itsy or itsy help for the command list. Add --help to a command for its syntax and options. Angle brackets mark required arguments and square brackets mark optional ones; omit the brackets when typing a command. A vertical bar separates alternatives: choose one.

Run site commands from the folder containing itsy.config.json. The new, setup, server, update, version, and help commands also work without a local site. Remote site commands use the current Git branch's saved deployment destination.

Create and develop

itsy new

itsy new [--starter|-s] <directory> [--skip-git]

Create a minimal site with an initial Git commit on main. The destination must be empty; use . for the current directory.

--starter, -s
Include example pages and team content.
--skip-git
Leave Git setup to you, for example when the site belongs inside a larger repository.

itsy dev

itsy dev [--port <number>] [--lan|-l]

Start the local server with live reload. It normally listens on loopback at port 3000 and tries the next port if needed. Press Ctrl-C to stop.

--port
Use a fixed port instead of trying alternatives. Use --port 0 to choose an available port.
--lan, -l
Allow full development access over HTTP on a trusted private or Tailscale IPv4 network. See testing on another device.

itsy status

itsy status

Validate local configuration, templates, content, and Git state. If this branch has a saved destination, also check the remote site over SSH and compare deployed code and Blog content. The command does not publish changes.

itsy reset

itsy reset

After confirmation, replace the local site's files and settings with a clean layout and homepage. Stop dev first. Git history and a private sibling backup are kept; the live site is unchanged.

Admin and email

itsy admin

itsy admin [email]

Add an admin to admin.emails in itsy.config.json, prompting for an address when omitted. Local access updates automatically. Commit and deploy to apply access on the live site. No invitation is sent. Edit admin.emails to view or remove access.

itsy email

itsy email
itsy email preview <sign-in|contact>

Set up Resend delivery and save credentials in the private .env file. The preview subcommand prints a sample HTML email from mailers/ without sending it. For example, itsy email preview contact renders the contact message.

New sites can preview local email without delivery credentials. Restart dev after changing Contact or email-preview settings. See Email and contact forms.

Set up and publish

itsy setup

itsy setup

Install Itsy Server on an existing supported Ubuntu LTS host over SSH. The command prompts for the server login. It does not provision a cloud server or configure your DNS. See server prerequisites.

itsy deploy

itsy deploy [options]

Publish the current Git branch's committed files. The first deployment asks for a destination and saves it for this branch in itsy.config.json. Deployment requires clean, committed source. In a larger repository, commit saved settings manually before deploying.

--configure
Confirm and save changes to this branch's destination.
--target <login>
SSH destination, such as root@example.com, or an SSH alias.
--domain <hosts>
Comma-separated hostnames or HTTP IPv4 addresses.
--name <name>
Stable site identifier on the server.
--https
Enable automatic HTTPS. Domains must point to the host and inbound TCP ports 80 and 443 must be reachable.
--email <address>
Contact address for Let's Encrypt.
--agree-tos
Accept the Let's Encrypt terms.
--www-redirect
Redirect WWW to the primary domain. Defaults to true for a new destination; use --www-redirect=false to disable it.
--expected-ips <ips>
Comma-separated expected DNS destination IPs for NAT or proxy setups.
--with-content
Also publish reviewed local Blog changes. Pull from this exact destination first. Content conflicts require an explicit choice.

Normal deployment updates code and CSS while preserving existing live Blog posts and cover photos. See Server setup and deployment and Blog content sync.

itsy https

itsy https [options]

Configure HTTPS for an already deployed site using this branch's destination. It accepts the destination and HTTPS options listed above, including --configure, but does not upload site code. --with-content belongs to itsy deploy and is rejected here.

itsy pull

itsy pull

Bring live Blog posts and referenced cover photos into the local site. Stop dev and commit local changes first. Review and commit the result afterward. Pull does not download templates, CSS, configuration, credentials, or sessions.

Manage deployed sites

These commands connect over SSH and work from any directory. They do not need a local site or saved deployment settings. Replace root@example.com with your server login, or omit it to be prompted. The CLI and server must use a compatible protocol.

itsy server list

itsy server list [ssh-target]

# Example
itsy server list root@example.com

List registered sites, their names and branches, HTTP and HTTPS domains, redirects, and host indexing policies. This is a read-only inventory of the sites on that server.

itsy server remove

itsy server remove [ssh-target] [site-name]

# Choose a site interactively
itsy server remove root@example.com

# Specify its site name
itsy server remove root@example.com old-bookshop

Take a site offline by unregistering its hostnames. Omit the site name to choose from the server's registered sites. Removal requires typing the exact site name and restarts the shared service, briefly affecting other sites.

Every release, content file, media file, session, and certificate stays on disk. Removal does not reclaim storage, and there is no automatic deletion or release-pruning command. If no HTTPS hostnames remain, automatic HTTPS is disabled while cached certificates are kept.

Retained content is not restored automatically by deploying the same site name again. Back up or pull the site before removal if you need to preserve its live content for a later deployment.

itsy server indexing

itsy server indexing [ssh-target] <hostname> <noindex|allow>

itsy server indexing root@example.com staging.example.com noindex

Set a registered hostname to noindex, nofollow, or use allow to add no restriction. Requires typing the exact hostname and restarts the shared service. Policies survive deployment, sync, and rollback. This controls search indexing, not access; see staging and search engines.

Backups and recovery

These commands use this branch's saved deployment destination. See Backups and recovery for the recovery workflow.

itsy backup

itsy backup <backup-file>

itsy backup ../bookshop.itsy-backup

Download a backup of the active code, configuration, CSS, Blog posts, and cover photos. Credentials, certificates, sessions, and custom app storage are excluded. The output file must not already exist. Keep it outside the site folder.

itsy rollback

itsy rollback [--list] [release-id]

Use --list to inspect retained releases. Without an ID, rollback selects the preceding release; supply an ID to select a particular one. After confirmation, it restores that release's code and CSS while keeping current live Blog content.

itsy restore

itsy restore <backup-file>

Replace live code and content with a backup after typed confirmation. Take a fresh backup first if you need to keep newer work. Restore and rollback preserve the server's current host indexing policy.

Versions and updates

itsy version

itsy version

Show the installed CLI version.

itsy update

itsy update

Download and verify the latest CLI and its bundled Itsy Server binaries. Remote servers and project files are unchanged.

itsy update-server

itsy update-server [--recover]

Update this branch's saved server using the bundled executable, after confirmation. Every site on the host restarts briefly. Configuration, credentials, and site data are preserved; the command does not migrate data formats or change service units.

--recover restores the executable after an interrupted upgrade. Check server compatibility and upgrade requirements before updating.
