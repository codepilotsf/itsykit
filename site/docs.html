FLEACMS DOCUMENTATION

Build the site and the server.

Install a single binary, build with HTML and CSS, and let Flea prepare your Ubuntu server, deploy over SSH and serve HTTPS. Mark the parts admins can edit.

The whole system

Flea is not only a content editor. It covers the developer's side of a small website and the server it runs on.

  • One binary, no dependencies. Install the CLI in a single command; there is no Go, Node, Python or database to add on your machine.
  • A local dev server. flea dev serves your files with live reload, LAN testing and local email previews.
  • Server setup. flea setup installs the bundled Flea server on a blank Ubuntu host over SSH — nothing to install by hand on the host.
  • Deployment. flea deploy publishes a committed Git branch over SSH. One host can serve many sites.
  • Automatic HTTPS. Flea requests and renews Let's Encrypt certificates and can redirect www.
  • Admin editing. Clients sign in and change text, photos, videos, repeatable lists and theme on the page.
  • Recovery. Backups, code rollback and restore are built in.
  • Agent-friendly. Portable instructions let coding agents build and import sites with you.

Install FleaCMS

For Apple Silicon Macs and x86-64 Linux. Open Terminal and run:

curl -fsSL https://fleacms.com/install.sh | bash

The installer downloads the matching executable, checks its SHA-256 checksum and installs it to ~/.local/bin/flea. No sudo and no extra runtime such as Go, Node or Python is required. It does not change your shell profile.

Use the installed copy in this terminal and check the version:

export PATH="$HOME/.local/bin:$PATH"
flea version

If needed, add that PATH line to your shell profile for future terminals. Then follow the quickstart below.

0.10.0 is available for Apple Silicon Mac and x86-64 Linux. The Mac binary is ad-hoc signed, not notarized; clean-machine testing is still in progress. Intel Macs and ARM Linux downloads are not included. 0.10.0 renames flea server sites to flea server list with no alias, and both flea server list and flea server remove can prompt for the server login. Managing sites on a server still requires a current server runtime; sites that have not moved to the bundled Contact app and protocol 23 must update first.

You can read the installer before running it, or download the Mac binary, Linux binary and checksums directly.

A site needs no frontend build pipeline or database. The CLI is a single binary, and the server needs nothing installed by hand either. Deployment uses Git and SSH; see Set up the server.

Your first site

Create a project and start the local server:

flea new my-site
cd my-site
flea dev

Enter a site name when prompted, then optionally add an admin email who can sign in and edit. You can also add one later with flea admin. Open http://localhost:3000.

Run flea dev again to replace this site’s running dev server, including when switching to -l or changing ports. Pull/reset operations are never interrupted. Stop a dev process started with an older binary manually once.

Edit site/index.html. The browser reloads when your files change. Add a little editable text:

<h1 snip>Hello, from our little corner.</h1>

While dev runs, Flea moves that text into flea/snips.json and leaves a generated reference in your HTML. Keep both files together in Git.

To start with example pages, use flea new --starter my-site. The default gives you a clean homepage.

Check your work

flea status

This validates your project without rewriting it. New projects have a Git repository on main, but no initial commit.

Test on another device

To use a phone, tablet or another computer on the same trusted network, start dev with:

flea dev --lan

flea dev -l does the same thing. Flea prints a Network URL using your computer's private IPv4 address. Open that URL on the other device; its /admin link opens sign-in. Without the flag, dev stays accessible only on your computer at localhost:3000.

This is the full dev site: approved admins can sign in, edit text and collections, upload photos and videos, use Theme, and save changes. Contact forms, browser reloads and dev diagnostics work over the network too. Each device signs in separately.

Sign-in codes and email previews

With email preview enabled, messages still open on the computer running Flea. Enter the code on your other device. To share a private preview, replace its loopback IP with the printed network IP, keeping the port and random path. Anyone with that link and network access can read the message, so keep it private. There is no public inbox.

LAN mode uses unencrypted HTTP. Use it only on a trusted network, never forward the development port, and restart dev after changing networks. VPN addresses may also appear. Your firewall must allow the selected port; guest Wi-Fi can block connections between devices. Use --port 3001 if you need a different port.

A folder you can follow

site/
Public HTML, CSS, images and other assets.
site/main.layout.html
The shared page wrapper.
flea/snips.json
Editable content and page metadata.
flea/data/
Optional JSON data you maintain in code.
flea/media/
Managed photos and videos.
mailers/
Private email templates.
.flea.config.json
Site settings and branch deployment destinations.
flea/runtime/
Private, Git-ignored runtime state.
flea/skills/
Portable instructions for coding agents.

Public URLs leave off site/. For example, site/images/logo.svg is served at /images/logo.svg. Keep secrets out of configuration, templates and Git.

Pages & templates

Add a page

Create site/about.html for /about. You can use site/about/index.html instead, but not both. Link to extensionless URLs without a trailing slash.

Share a layout

The default wrapper is site/main.layout.html. Put {slot} where the page content belongs.

<header>Our studio</header>
<main>{slot}</main>
<footer>Thanks for stopping by.</footer>

For a different wrapper, put this comment at the very start of a page:

<!-- flea
layout: /custom.layout.html
-->

Preserve the generated layout's app.current_admin conditional blocks, CSRF meta tag and admin toolbar include. They connect the page to the admin editor.

Reuse a partial

Create site/_card.html, then include it with {render card}. Relative names resolve beside the calling template. {render /shared/card} selects site/shared/_card.html.

Settings and structured data

Public settings live under app in .flea.config.json. Use {app.site_name} in your templates. A file named flea/data/team.json is available as data.team.

{#if app.phone}
  <p>Call {app.phone}</p>
{/if}

{#each data.team.members as member}
  <p>{member.name}</p>
{:else}
  <p>Meet the team soon.</p>
{/each}

Conditions take dotted paths, not JavaScript expressions. Use {#unless app.phone}...{/unless} for a negative condition. Both support {:else} and {:else if dotted.path}.

Make content editable

A snip is a piece of content the admin can change. Mark an element with a bare snip attribute:

<section snip>
  <h2>Made just around the corner.</h2>
  <p>Visit our studio on Saturday.</p>
</section>

Dev extracts the inner HTML into JSON and replaces it with a generated snip directive. Let Flea generate the ID and keep it unchanged. The JSON entry becomes the source of the editable value.

Classes, layout and other attributes stay in the template. Don't nest snips or put template directives inside a new editable region. Use dedicated image and video snips for media.

Admins can format text and edit page titles and descriptions using Page details. Changes are published with the page's Save button.

Photos & videos

Photos

<img snip src="/images/studio.jpg"
  alt="The studio in the afternoon"
  width="1200" height="800" />

Dev imports a local JPEG or PNG into managed media and creates the source and alt-text bindings. Keep dimensions, classes and links in your HTML. Don't combine a media snip with srcset, picture or competing source elements.

Admins click a photo in Edit mode to choose or upload a replacement. Save publishes it; Cancel discards the draft.

Videos

<video snip src="/videos/studio.mp4" controls></video>

Use a fast-start MP4 with H.264 video and optional AAC-LC audio, up to 25 MiB. Flea does not transcode videos. Admins can replace the video or its poster from the page editor.

Video storage is limited to 64 MiB, including retained replacements. Managed MP4 files are Git-ignored. Restore missing files on a fresh checkout with flea pull --snips-only before validation.

Repeatable content

A multisnip lets an admin add, remove and reorder items such as team members. Give the group a name and name its editable fields:

<article multisnip="team">
  <h2 snip="name">Sam Rivera</h2>
  <p snip="title">Studio founder</p>
  <img snip="photo" src="/images/sam.jpg" alt="Sam" />
</article>

Dev turns the seed into a loop. Admins use the on-page Add tile, remove button and drag handles. Arrow keys on a handle can reorder items too.

Keep each group on an individual page, with one root element. Don't nest groups or place them in layouts, partials or other loops. Video fields are not supported in multisnips.

Hand over the editing

Add an approved admin from your site folder:

flea admin admin@example.com

This adds the address to admin.emails. Admins visit /admin and sign in with an emailed code. All approved admins have the same editing access.

Editing starts enabled. Click text or media, make changes, then use Save or Cancel. Both keep editing on. Save updates the page in place without reloading it; Cancel returns to the latest successful save. The Theme panel has its own save and cancel controls.

New local sites preview email in the browser without sending it. Production needs HTTPS and real email delivery. Commit and deploy admin-list changes before sharing the live sign-in link.

Sessions have a default 30-day idle window. Set admin.session_idle_days to a value from 1 to 365. An empty admin list disables live sign-in.

Your CSS, your design

Generated sites include Prewind 1.3.1. Start with global styles, then use utilities for individual adjustments. There is no CSS build step.

Edit site/css/theme.css for colors, fonts and spacing tokens. Put shared rules in site/css/global.css inside @layer styles. Admins can change supported theme variables through the Theme panel.

Icons

{icon arrow-right}
{icon search size="20" aria-label="Search"}

Dev downloads only the referenced Lucide icons into flea/icons/. Commit the cache for offline use. Status checks do not download icons.

Put your site online

Flea hosts multiple sites on one Ubuntu server. You'll need SSH access, a domain pointing to that server, and inbound TCP ports 80 and 443 for HTTPS.

Set up the server

flea setup

Run this from your computer and point it at a blank Ubuntu server over SSH. Flea installs the bundled server there and prepares the host to serve your sites. There is nothing to install by hand — no Go, Node, Python or database on the host. Use a server with ports 80 and 443 available for HTTPS.

Deploy a branch

flea deploy

The first run asks for the server, domain and HTTPS preferences. It saves that branch's destination in .flea.config.json and offers to commit your reviewed files. Deployment publishes committed source and requires a clean working tree.

Each branch has its own destination. Use flea deploy -configure to change it, or flea https -configure to revisit just the HTTPS settings. Configuring a destination does not create DNS records.

Keep admin changes

Normal deployment preserves live editable content and theme changes. To bring those edits into your local project, stop dev and run:

flea pull

Use --snips-only or --theme-only to narrow a pull. Review and commit the result.

To deliberately publish local content or theme edits, first establish a pull baseline, then use the relevant option:

flea deploy --with-snips
flea deploy --with-theme

You can combine the options. Conflicts require an explicit choice between the live and local changes.

Email & contact forms

New sites set dev.email_preview to true. Local sign-in and contact emails open as private browser previews without Resend credentials. Preview messages expire and disappear when dev stops.

For real delivery, run:

flea email

Local credentials belong in the private, Git-ignored .env file. For real local delivery, set the preview toggle to false and restart dev. Production ignores the preview toggle and needs server-side mail configuration.

A contact form

Enable the bundled Contact app under apps.contact in .flea.config.json, with a mount and the recipient in email.to. This replaces the removed top-level contact settings and the old /_flea/contact route: there is no alias or automatic migration, and deployment requires protocol 23. Create site/contact/index.html and a mount-relative site/contact/thank-you.html. The form includes an explicit CSRF control and posts to the mount:

<form method="post" action="/contact">
  {csrf}
  <label>Name <input name="name" required maxlength="100" /></label>
  <label>Email <input type="email" name="email" required /></label>
  <label>Message <textarea name="message" required maxlength="5000"></textarea></label>
  <div hidden><label>Leave empty <input name="website" tabindex="-1" autocomplete="off" /></label></div>
  <button type="submit">Send message</button>
</form>

Success redirects to the mount's thank-you page with a visitor-bound notice. Messages are emailed, not stored, and validation re-renders the form with safe values on error. There is no general-purpose form backend.

Email templates

Customize mailers/*.email.html and *.email.txt. HTML emails share mailers/main.layout.html. Keep its slot and use escaped app.* and email.* values.

flea email preview sign-in

This renders a sample without sending an email.

Backups & recovery

Make a backup

flea backup ../before-redesign.flea-backup

This downloads the active site's code and editable content, including managed media and theme. Choose a new file path outside your site and keep a separate copy. Credentials, certificates, deployment mappings and sessions are excluded.

Roll back code

flea rollback --list
flea rollback

Rollback republishes earlier code while retaining current admin content and theme. It asks for confirmation before acting.

Restore a backup

flea restore ../before-redesign.flea-backup

Restore replaces live code, site configuration and editable content. It requires typed confirmation. Take a fresh backup first if newer content matters.

Reset a local project

flea reset returns the local site to a clean starting point after confirmation. It replaces local files and settings, keeping Git history and a private sibling backup. It does not reset a live site.

Keep Flea up to date

Update your installed CLI with:

flea update

Flea verifies the downloaded checksum and version before replacing the executable. A local update does not update your remote host. From a configured site, explicitly run:

flea update-server

Server updates affect every site on that host and ask before restarting it. Keep backups and check compatibility first. An interrupted update can be recovered with flea update-server --recover.

AI-assisted development

Flea projects are friendly to coding agents. Portable instructions live in the repository, so an agent can follow your conventions, import an existing site and keep editable content intact.

  • flea/skills/import-brochure/SKILL.md guides imports and redesigns through content inventory, two design directions, a sample page, local assets and editable snips.
  • flea/skills/fleacms-site/SKILL.md covers research-first site building with real assets and design-review checkpoints.
  • AGENTS.md points your agent at both skills and the project rules.
  • No plugin, account or special runtime is required; plain HTML and Markdown are all an agent needs to read.

These guidance files stay in Git but are excluded from public serving and deployment.

Where Flea fits

Flea is built for small content websites. It is not a general application framework or an ecommerce platform.

  • No general field schemas, arbitrary server-side application code or general-purpose form backend.
  • No video transcoding or video fields in collections.
  • No content revision-history interface. Use the backup and recovery commands.
  • Rich text is sanitized; editable content does not accept unrestricted HTML.
  • Downloads currently cover Apple Silicon macOS and x86-64 Linux. Clean-machine testing is in progress.

The source repository is private. The binaries are free to use, without an account or license key.

Release notes

0.10.0 · October 5, 2026

Flea renames flea server sites to flea server list with no alias. Both flea server list and flea server remove now ask for the server login (for example root@fleacms.com) when you omit the SSH target, and flea server remove without a site name lists the managed sites and asks you to choose one by its exact name before the existing confirmation. Listing shows each site's name and branch, then HTTPS domains, then HTTP-only domains, then redirects. Removal is unchanged: the list is read-only, removal only unregisters routing and deletes no files, and it restarts the shared server, so other sites are briefly unavailable. These commands need a current server runtime. Run flea update for the CLI.

0.9.0 · October 5, 2026

Flea now bundles the Contact app and adds server-wide site administration with flea server sites and flea server remove. Enable a form under apps.contact with a mount and recipient; it posts with an explicit CSRF control to the mount, and success redirects to the mount-relative thank-you page. This replaces the top-level contact settings and the /_flea/contact route, and deployment requires protocol 23; there is no alias or automatic migration, so update the server and existing sites together. Large static assets and managed photos now stream from disk instead of loading fully into memory. Run flea update for the CLI, then update the shared server separately with flea update-server.

0.8.1 · October 3, 2026

Starting Flea no longer duplicates its runtime and media rules in .gitignore when other entries follow them. Existing file contents are preserved. Run flea update to install the fix.

Need a hand?

Start with flea status to check your site and flea <command> --help for a command's options.

If you're testing Flea, send feedback to the person who invited you. Include your operating system, processor, Flea version, the command you ran and the exact error. Leave out credentials, sign-in codes and private runtime files.
